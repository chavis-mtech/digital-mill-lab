# Frontend Guide — apps/web

> Owner: frontend-foundation (wave 1). Audience: frontend-exec, frontend-ops and anyone adding UI.
> Read `docs/SPEC.md` §0 (honesty rules) first. This guide describes what exists in `apps/web` today.

| Fonts | self-hosted via `@fontsource-variable/{inter,noto-sans-thai,jetbrains-mono}` (no network at build) |

```bash
pnpm install                          # repo root
pnpm --filter web dev -p 3106         # API_PORT=8106 to point the /api/v1 proxy at your API
pnpm --filter web typecheck           # tsc --noEmit
pnpm --filter web lint                # eslint (flat config; `next lint` no longer exists)
pnpm --filter web test                # vitest: i18n TH/EN key parity
pnpm --filter web build               # set API_PORT / API_INTERNAL_URL at build time too (rewrites are baked in)
```

The web app calls the API **same-origin**: `next.config.ts` rewrites `/api/v1/*` → `API_INTERNAL_URL` or
`http://127.0.0.1:${API_PORT:-8000}`. `output: "standalone"` matches `infra/docker/web.Dockerfile`.

## 3. How to add (replace) a demo page

1. Open your placeholder, e.g. `app/demo/executive/page.tsx`, and **replace the whole file**. Keep the shell —
   `app/demo/layout.tsx` already renders the Synthetic Data banner, top bar, DemoControls and sidebar.
2. Put feature code in `features/<module>/**` (your owned folder) and keep `page.tsx` thin.
3. Pick the layout that matches SPEC §5. `route` pulls title/description/status from `content/routes.ts`:

```tsx
// app/demo/executive/page.tsx  (server component is fine; feature components are "use client")
import type { Metadata } from "next";
import { ExecutiveDashboard } from "@/features/executive/executive-dashboard";
export const metadata: Metadata = { title: "Executive Control Tower" };
export default function Page() { return <ExecutiveDashboard />; }
```

```tsx
// features/executive/executive-dashboard.tsx
"use client";
import { ExecutiveLayout } from "@/components/layouts/layouts";
import { KpiCard } from "@/components/data/kpi-card";
import { QueryState } from "@/components/states/states";
import { useApiQuery } from "@/lib/api/hooks";
import { useDemo } from "@/lib/demo/context";

export function ExecutiveDashboard() {
  const { period } = useDemo();
  const kpis = useApiQuery("/api/v1/executive/kpis", { params: { query: { period } } });
  return (
    <ExecutiveLayout
      route="/demo/executive"
      kpis={kpis.isPending
        ? Array.from({ length: 8 }, (_, i) => <KpiCard key={i} loading />)
        : kpis.isError ? <KpiCard error={kpis.error} />
        : kpis.data.kpis.map((k) => <KpiCard key={k.key} kpi={k} data-tour={k.key === "oer_pct" ? "exec-kpi-oer" : undefined} />)}
      aside={/* insights, alerts */ null}
    >
      {/* charts, tables */}
    </ExecutiveLayout>
  );
}
```

Layouts: `ExecutiveLayout` (header + KPI grid + main/aside), `OperationsLayout` (header + module tabs from the
route registry + optional toolbar), `AIWorkspaceLayout` (main + evidence rail; rail becomes a drawer below xl),
`DocsLayout` (prose column + optional "on this page" TOC). All accept `route`, `title`, `description`,
`feature`, `actions`.

4. Add `data-tour="<target>"` to the element your tour step highlights (see §9).
5. Give the page a `metadata.title`.

## 4. Fetching data

* `useApiQuery(path, init?, options?)` — typed GET. `path` autocompletes from the contract; `init.params.query`
  / `init.params.path` are typed. It automatically sends `as_of` + `scenario_id` (query) and `X-Demo-Session` +
  `X-Demo-Role` (headers) from DemoContext, and its query key includes them, so switching scenario/role/clock
  refetches. Pass `{ withClock: false }` for catalogs/metadata.
* `useApiMutation(path, { invalidate: [...paths] })` — typed POST with the same context. Writes need a session
  (we create one on first visit: `POST /api/v1/demo/session`, stored in `localStorage.dml_demo_session`).
* `period` for endpoints that accept it: `useDemo().period` (`today | 7d | 30d`, derived from playback).
* Errors are `ApiRequestError` (`status`, `code`, `message`, `details`, `requestId`, `isNotImplemented`,
  `isUnavailable`, `isForbidden`, `isRateLimited`, `stubInfo`). 501/4xx are not retried.
* **Never compute business numbers in TypeScript** (ADR-002). Format only (`lib/format.ts`). If a number is
  missing, request it from the backend owner.

## 5. States (mandatory)

Every data view handles loading / error / not-implemented / empty:

```tsx
<QueryState query={q} isEmpty={(d) => d.items.length === 0}>
  {(d) => <DataTable data={d.items} columns={cols} caption="Alerts" exportName="alerts" />}
</QueryState>
```

`ErrorState` maps errors automatically: 501 → `NotImplementedState` (shows owner + task from the envelope),
network/proxy → "API unreachable" + retry, 403 → "not available for this viewpoint", 429 → rate-limited.
Charts, `KpiCard` and `DataTable` accept `loading` / `error` / `empty` props directly. Never show made-up
numbers in place of a stub.

## 6. Picking a component / chart

| Need | Use |
|---|---|
| Headline number + delta + sparkline | `KpiCard kpi={KpiValue}` (delta colour comes from API `good_direction`) |
| Change over time (1–6 series) | `TimeSeriesChart` / `TrendChart` — `series: Series[]`, `anomalies`, `normalRange`, `thresholds` |
| Forecast with uncertainty | `AreaBandChart band={BandSeries} actual={Series} baseline={Series}` (always pass the naive baseline) |
| Compare categories / what-if vs baseline | `BarChart` (grouped, stacked, horizontal; `kind: "what_if"` adds a hatch) |
| Hour × day intensity | `HeatmapChart` (`scale="sequential"` magnitude, `"diverging"` deviation) |
| One bounded value | `GaugeChart` (bands from API thresholds) |
| Tabular records | `DataTable` (sort, search, density, pagination, CSV with UTF-8 BOM for Thai) |
| Evidence for an anomaly/insight | `EvidencePanel evidence factors assumptions` (heading always says "not proven causes") |
| Formula transparency | `FormulaPanel formulas={Formula[]}` (display only) |
| Record-changing action | `ConfirmDialog` (mandatory before any write) + `toast` |
| Alert severity / equipment health | `SeverityPill`, `AlertBadge` |

Chart rules (from the dataviz method): one y-axis only (two scales → two charts); series colours follow entity
order `--chart-1…6` (validated colour-blind safe; never cycled, never by rank); provenance = line pattern
(solid actual · dashed forecast · dotted what-if); every chart renders a keyboard legend and a data-table
toggle through `ChartFrame`. Status colours are reserved for status.

## 7. Provenance, status and honesty components

* `ProvenanceBadge provenance={x.provenance}` next to **every** number (SPEC §4.A). Icon + border pattern +
  text, tooltip shows source / as_of / model version.
* `StatusChip feature="<key>"` reads `content/status.ts`. Rules: only the **orchestrator** sets
  `implemented`; owners may move their own entries `planned → partial/prototype` with evidence in their
  status file. P2 concepts carry `target: "prototype"` and render "Planned → Prototype".
* `SyntheticDataBanner` is mounted by the shell — never hide it.
* `Disclaimer kind="roi"` renders the exact ROI sentence; also `synthetic`, `advisory`, `simulatedLive`,
  `roles`, `independent`, `riskScore`. Put `roi` next to every money figure, `riskScore` next to risk scores.
* Roles are labelled "simulated viewpoint — not authentication" in DemoControls; keep that wording.

## 8. i18n (ADR-008)

* Locale lives in the `dml_locale` cookie (TH default). No route prefix.
* Create a bundle per feature, named `*.i18n.ts`, default-exporting `defineMessages({ th, en })`. TH is the
  source of truth; `en` must have the same keys (tsc enforces it; `pnpm --filter web test` re-checks every
  `*.i18n.ts` file for identical keys, same value kinds and no empty strings).
* Client: `const t = useT(messages)`; server: `const t = await getT(messages)`. Functions are allowed:
  `rows: (n: number) => \`${n} rows\``. Inline content objects can use `Bilingual` + `{x[locale]}`.
* API labels: prefer API bilingual fields (`name_th` / `label_th`) when present.
* Dates/numbers: `formatDate`, `formatNumber`, `formatValue` (Asia/Bangkok, Gregorian calendar in TH).

## 9. DemoContext and the guided tour

`useDemo()` → `{ asOf, scenarioId, playback, role, locale, sessionId, period, request, live, setScenario,
setPlayback, setAsOf, setRole, apply, reset }`. State mirrors to URL params (`as_of`, `scenario`, `playback`,
`role` on /demo and /docs) and `localStorage.dml_demo_ctx`. A URL carrying demo params is authoritative (a
missing `as_of` = server-resolved clock, i.e. the scenario's `focus_ts`). Simulated live calls
`POST /api/v1/demo/tick` every 6 s and stops with an honest "not available" chip while that endpoint is a 501.

Tour steps live in `content/tour.ts` (scenario `PRESS_VIBRATION_ANOMALY` throughout). Targets to implement:

| 3 Abnormal signal | /demo/maintenance/equipment | `equipment-sensor-trend` | frontend-ops |
| 4 AI proposes inspection | /demo/maintenance | `maintenance-recommendation` | frontend-ops |

Until a target exists the tour shows its narration plus "This view is not built yet".

## 10. Design tokens (summary)

Defined in `app/globals.css` as CSS variables (light on `:root`, dark on `.dark`; system default, user choice
in `localStorage.dml_theme`, applied pre-paint). Tailwind utilities map 1:1: `bg-surface`, `bg-surface-2`,
`text-muted-foreground`, `text-subtle-foreground`, `border-border`, `bg-primary` (deep navy), `bg-accent`
(restrained teal), status `success|warning|critical|maintenance|info` each with `-fg` (text-safe) and `-soft`
(background), provenance `prov-actual|prov-forecast|prov-whatif`, charts `chart-1…6`, sequential `--seq-1…6`,
diverging `--div-*`. Type scale 2xs…5xl (15px body), `.tabular` for numbers, Thai gets the Noto Sans Thai face
and taller line-height via `:lang(th)`. Radius `--radius` 8px, shadows `shadow-xs…lg`, motion tokens
`--duration-*`/`--ease-*`; `prefers-reduced-motion` disables animation globally. Text tokens meet WCAG AA
(axe: 0 serious/critical on the public pages, both themes, both languages).

## 11. Don'ts

* Don't import `fixtures/ui-kit.ts` outside `/ui-kit`.
* Don't hard-code KPI values, fake predictions or "sample" numbers in demo pages.
* Don't remove the banner, provenance badges, status chips or disclaimers.
* Don't edit `components/**`, `lib/**`, `content/status.ts` or `app/demo/layout.tsx` — ask frontend-foundation /
  the orchestrator (write a Request in your status file).
